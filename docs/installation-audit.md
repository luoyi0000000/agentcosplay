# 1.1.0 安装与中断审查

2026-09-19。本次按新增的人工安装、整仓库 Agent 安装、本地数据与共享 Runtime 要求检查既有交付及新增安装代码。以下记录真实发现和验证结果，不宣称已完成所有宿主 UI 验收。

## 发现并修复的问题

| 问题 | 修复 | 验证 |
|---|---|---|
| 原快捷安装器只放 Skill，完整 Runtime 仍需手工搭建 | install.py 安装核心、锁定依赖、原生配置和 Skill；两种安装入口复用 | 隔离目录全新安装及真实 MCP 工具发现 |
| CLI 默认把数据库放当前目录 data，容易与源码一同删除 | 系统用户数据目录；拒绝源码、Git、程序目录与人物数据重叠 | 三平台路径、目录重叠和符号链接测试；移动源码后记忆可读 |
| 启动器 python -m 可能执行当前目录同名包，绕过活动版本 | 隔离模式 -I，清除 PYTHONPATH/PYTHONHOME | 构造恶意同名包，测试先失败再通过 |
| HTTP 配置目标可位于 Git，可能把 Bearer 提交进去 | 所有凭据宿主路径拒绝 Git 祖先；token/配置/备份私密写入，不回显 | Git 宿主目录回归先失败再通过 |
| 强制中断会遗留独占文件锁，recover 无法进入 | 使用系统文件锁，进程退出自动释放；保留稳定锁文件 | 真实子进程 os._exit(9) 后恢复测试先失败再通过 |
| 更新过程中可能覆写用户刚修改的配置、残留已删除的旧 Skill 文件 | 修改前比较原内容，冲突拒绝；只清理安装记录中未被改写的旧文件 | 事务恢复拒绝外部改写；原生配置合并/冲突测试 |
| doctor 可能漏报丢失的宿主服务项 | 检查目标项确实存在及内容一致，再检查 Skill 与 Runtime | 原生配置与实际安装验收 |
| AstrBot HTTP 需要明确传输类型，只有 URL 不够 | 原生配置加入 transport: streamable_http | 对照官方客户端源码；生成配置断言 |

## 已执行验收

- 自动化测试：68 项通过，覆盖身份/角色隔离、授权、存储、迁移隐私、安装路径、中断恢复与实际 MCP 客户端。
- Ruff、格式检查、mypy 通过；锁文件校验通过。
- `python -m scripts.check_installation`：全新依赖环境，安装 → 创建记忆 → 断开重连 → 移动源码 → 两个独立 HTTP 客户端接同一运行进程并双向读写 → 更新 → 回滚 → 卸载保留数据库 → 重装继续召回。
- 导出到另一份 Runtime/数据库：定义、关系与成长保留；显式选择的角色记忆保留，默认包不含该记忆；已有真实用户记忆排除测试继续通过。
- failed-update 测试确认候选健康检查失败后活动版本、原人物数据不变；恢复日志会拒绝覆盖中断后的用户编辑。

安装测试只修改临时宿主目录，测试人物全部合成，结束删除临时安装及数据。没有更改开发者的真实 Codex/Hermes/AstrBot 配置。

## 明确边界

- 实机验证环境为 macOS arm64 / Python 3.11.15。Windows/Linux 路径分支有测试，尚无对应实机验收。
- HTTP 验收是两个真实 SDK 客户端，不是已经安装并连通真实 Hermes、AstrBot、QQ 或手机。最终用户仍需重载宿主、启用 Skill，并验证消息渠道与身份映射。
- Marketplace 文件已提供，不代表公开市场收录或所有 ChatGPT 账号均可导入。单独 marketplace/ZIP 只提供对话规则，完整持久化走安装器。
- 不增加作者云服务或数据库同步。共享 HTTP 采用现有前台 Runtime，由用户现有进程管理器负责常驻；分离主机/容器须实际配置网络与认证，不能照抄 localhost。
- schema 仍是 1，没有本次数据迁移。旧源码内 data 不自动移动；用显式导出/导入或停机备份迁移。未来破坏性 schema 变更必须先补迁移和回退验证。
- 安装配置要在宿主停止时修改。事务日志和写前检查保护中断与已检测的外部编辑，但不把多个文件伪装成跨进程数据库事务；外部程序仍在同时写配置时不能保证互相协调。
