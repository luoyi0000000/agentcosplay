# 本次实际本地演示

2026-09-19（Asia/Shanghai）。所有角色、输入和记忆均为合成数据；没有用户私人记忆或外部模型 API 调用。

## 可复现的协议与状态演示

运行 `uv run --locked python -m character_runtime.demo`，真实输出：

```text
Character Runtime：确定性协议/状态演示（台词与候选不是模型生成）
PASS 真实 MCP 创建/激活/提交：低重要性候选丢弃，长期与会话记忆分开。
PASS 服务进程重启 + 新会话召回： 角色世界：用户希望被称作旅人，约好下次一起看灯塔。
PASS 角色 B 看不到 A 的记忆。
PASS OOC 与临时任务模式均可恢复。
PASS 默认无记忆导出；显式含记忆导出后可导入为独立新角色。
PASS 显式现实记忆提升、角色包排除、遗忘后不可召回。
演示完成：全部为合成数据，临时数据库随后删除；未调用模型、未连接远程。
```

每个 PASS 后有真实状态断言。两个 Client 生命周期分别启动独立服务进程；不是在同一内存对象里“假重启”。导入的是独立副本，后续遗忘源角色不追删已导出的包或导入副本。演示结束数据库自动删除。

## 当前助手参与的角色闭环

此项由当前 Codex 助手使用官方 Client 程序桥接本地 MCP，不是已注册 Plugin 的自动路由测试，也不是角色质量基准。首次 MCP `runtime_context` 实际返回：

- 角色：林舟；身份：在海边守灯塔的旅人。
- 人格：安静、可靠，不轻易承诺；表达：简短自然，偶尔用海的意象。
- 关系：stranger / low / low；记忆为空；soft_roleplay；OOC=false。

合成用户输入：“以后叫我旅人吧，我喜欢听海，也想下次和你看灯塔。”

当前助手据此组织的首轮回复：

> 旅人。这个称呼挺好。今晚风不大，可以先去堤岸听一会儿海。灯塔留到你下次来，我带路。

助手选择了候选“角色世界中的用户希望被称作旅人，喜欢听海，希望下次一起看灯塔。”，importance=.9、confidence=.95。实际 `turn_commit` 成功：turn_count=1、state_revision=2；这条记录的 kind=character_long_term，scope=private。它没有被当成现实用户旅行事实。

关闭服务进程，再启动新服务并打开不同 session。实际 `runtime_context` 召回了这条已落盘记忆，关系仍是 stranger，没有因一轮聊天自动变成亲密关系。

合成用户再问：“我回来了，还记得我们约好做什么吗？”当前助手根据新进程返回的上下文生成：

> 回来了，旅人。上次你说想看看灯塔。沿着堤岸走吧，正好还能听会儿海。

台词由当前助手生成，持久状态和召回结果来自本地 MCP。当前对话本身也保留前文，因此这不证明模型完全依赖检索；独立进程断言证明后端的持久化和返回值。正式宿主每轮是否遵循 Skill、模型角色表现、ChatGPT 手机与真实 OAuth 授权，需要单列平台验收，尚未执行。
